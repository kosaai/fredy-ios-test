## Stage 1 verified upstream contract (read-only installed Fredy 31.0.0)

- `lib/api/routes/jobRouter.js:187–209`: POST `/api/jobs/{jobId}/run`; no JSON body required. 202 `{message: "Job run accepted"}`; 403 not allowed, 404 missing, 409 tour/already running, 500 failure. Manual runs can search a disabled job; changing enabled is not a run or a cancellation.
- `jobRouter.js:334–356`: PUT `/api/jobs/{jobId}/status`, JSON `{status: Bool}`; HTTP 200 EMPTY acknowledgement. 403 demo/access denied, 404 missing, 500 failure. No new enabled alias, string Bool or upsert is needed.
- GET `/api/jobs/` adds actual `isOnlyShared` via access policy. `lib/services/security/access.js` permits owner/admin modification; a shared viewer cannot run/change the job. Missing permission/status fields must remain unknown, not default false.
- `jobStorage.setJobStatus` stores only enabled for the exact id. GET root includes disabled jobs and converts enabled to Bool. A read-back must confirm enabled before changing the displayed switch.
- Existing execution service logs provider failures without a provider outcome resource. Stopped/false/empty counts are not proof of success. No live development-tool run/PUT is needed to inspect these contracts.

### No-notifications boundary

GET jobs redacts channel fields and exposes `notificationAdapter` as an array (`toClientJob`, jobRouter lines 74–82). Run has **no per-request suppress-notifications argument**: the normal pipeline can use saved channels. The new Jobs controls therefore require a confirmed empty array before Run or enabling scheduling, checked again in a fresh preflight GET. Missing/malformed/nonempty channels block those actions; disabling a currently enabled job remains possible without editing channels. Only the array's emptiness is retained, not names, IDs, fields or credentials. We do not remove channels as a hidden workaround. Concurrent other clients can change server configuration between GET and a write; this client cannot promise server-wide atomic notification suppression. The pre-existing Home bulk-run flow is preserved, not extended/reconfigured in this stage.
